## Performance and lifecycle evidence

- Desktop shared map chunk: 500.93KB minified, 147.37KB gzip. Regular quest JSON:
  1,462,030 bytes. These sizes alone do not establish a performance defect.
- One development-mode Customs navigation: DOMContentLoaded 1.37s. StrictMode
  issued duplicate SVG requests. This is not a production startup benchmark.
- Ten alternating Customs/Woods changes followed by garbage collection:
  documents 1→1, DOM nodes 2,178→2,178, JS listeners 295→295, used heap
  14,772,716→15,884,564 bytes. This does not establish a memory leak.
- Map removal, ResizeObserver disconnect, and most timer/listener cleanup exist.
  Whole-layer rebuilds and repeated SVG parsing remain profiling hypotheses.
- Layer filtering and composition have domain ownership; similar layer-toggle
  orchestration remains duplicated between desktop and companion. Do not combine
  a broad structural rewrite with these behavior changes.

## Quest image/source decision

The [Tarkov.dev schema](https://raw.githubusercontent.com/the-hideout/tarkov-api/main/schema-static.mjs)
and JSON task endpoint expose `wikiLink` and `taskImageLink`. The latter is a
generic quest image, not an objective-location guarantee. API availability and
the API software license do not establish per-image redistribution permission.
Wiki file-license pages could not be reliably retrieved during this audit.
The initial implementation deferred third-party images; the subsequent
user-authorized artwork integration is recorded below.

The user selected objective-centered previews of existing bundled maps. Preserve
the CC BY-NC-SA 4.0 attribution and upstream usage restrictions recorded in
`ASSET_LICENSES.md`; previews do not grant new rights or claim anti-cheat approval.
The initial scope added only Wiki URLs matched to existing quest IDs, with
provenance and checksums; no broad quest/artwork refresh is authorized by this feature.

## Implemented feature scope

- Extraction names now use a screen-space layout independent of transit labels.
  Initial bounds fit the available map viewport; active/selected exits take
  placement priority. Leader lines, clamping, and a numbered scrollable list
  handle edges and crowding. Marker tooltips and accessible names retain the
  full text. Labels sit below popups and do not capture map gestures; list
  actions are isolated from map shortcuts. Existing category/floor filtering
  and active-extraction markers remain in effect.
- Active and panel-focused quest markers resolve exact task/objective IDs against
  shared validated bundled catalogs. Focus waits for POIs across map/floor
  changes. The read-only dialog shows summary, objective details, uncertainty
  for possible locations, and an attributed objective-centered local map preview.
  Failure states retain marker text and offer retry. Validated Wiki references
  are optional; no Wiki HTML or remote quest images are embedded. Native URL
  opening uses an explicitly scoped Tauri opener permission.
- Companion pins have 44px individual deletion and a current-map clear action.
  Changes update state immediately, clear stale selection/focus/popups, and
  persist only validated local pins. Other maps and non-user markers remain.
  Creation observes the existing 500-pin limit; storage failures produce a
  visible unsaved-change message. Touch and keyboard controls are isolated
  from waypoint creation.
- Related fixes render POI tooltips as text and restrict the Enter-to-create
  shortcut to the map itself. SVG fetches abort on cleanup. No unrelated relay,
  native filesystem, dependency, or schema-hardening backlog item was changed.

Settings schema v2 and room protocol v1 are unchanged. The optional quest catalog
mode is process-local overlay metadata, with regular-mode compatibility for old
snapshots. Quest profiles/progress and companion pins never enter the relay.
Only the small Wiki-reference data family was added to the asset ledger;
existing quest snapshots and artwork were not refreshed.
